# Исправление зависших рефиллов

## Что исправить
- Запретить запуск рефилла для заказов, по которым уже оформлен возврат, и не позволять рефиллу перезаписывать `refunded`.
- Не оставлять запрос бесконечно в `requested`: добавить серверное состояние ошибки/таймаута и вернуть заказ в корректный конечный статус.
- Связать запуск рефилла с реальным вызовом API поставщика; если поставщик не поддерживает refill для заказа или это тестовый заказ, сразу вернуть понятную ошибку без смены статуса.
- При проверке состояния синхронизировать успешный ответ поставщика с `order_refills.completed` и `orders.completed`.
- Исправить уже зависший заказ: поскольку по нему возврат был завершён раньше запроса рефилла, восстановить `refunded`, а ошибочный рефилл закрыть как отменённый.

## Технические детали
- Серверная функция будет единственной точкой запуска: сначала проверка владельца/гарантии/возврата, затем provider API, и только после подтверждённого принятия — запись рефилла.
- Добавить идемпотентность, timestamps ответа поставщика и безопасную обработку недоступного API.
- Добавить миграцию для защитных проверок и reconciliation старых зависших записей; UI продолжит брать статус только из базы.

## Проверка
- Заказ с возвратом не может перейти в refill.
- Ошибка API не создаёт активный refill и не меняет статус заказа.
- Успешный provider status завершает refill и возвращает заказ в «Завершён».
- Перезагрузка и повторный вход показывают тот же серверный статус.
